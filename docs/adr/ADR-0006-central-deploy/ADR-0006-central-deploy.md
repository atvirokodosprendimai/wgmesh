**Served-path change:** `wgmesh -deploy` (`main.go:176` calling `Mesh.Deploy`) refuses a state file whose values could reach a node's root shell, writes every value it sends to a node quoted for that shell, configures every reachable node even when another one is down and ends with one list of which node failed in which phase, and gives a mesh whose nodes all have private SSH addresses an endpoint per node instead of none.

## Decisions

M answered the seven questions of the first draft on 2026-11-15, all at once (M 2026-11-15: "Pagal visas rekomendacijas, ADR po ADR (Recommended)"): every one is decided as the recommended option, recorded here. The Decision section below is written on them.

1. **A failing node does not stop the run** (#865). Option (a): continue with the other nodes by default, one summary of failures, exit non-zero; no flag. Only a run that already failed behaves differently, and the exit code stays non-zero. (M 2026-11-15, all questions: "Pagal visas rekomendacijas")
2. **Two validation classes** (#868). Class A (a character a shell or wg-quick file gives a meaning to, a control character, an empty interface name) is refused from release N; class B (a value that parses wrongly but cannot reach a shell) warns at N and is refused at N+1. (same answer)
3. **An all-private mesh gets endpoints** (#866 item 2). When every node's SSH host is a private IP address (`net.IP.IsPrivate`), each node's endpoint is `<ssh host>:<listen port>`, local node included; mixed meshes are unchanged. (same answer)
4. **An operator-written `public_endpoint` wins over detection.** It is no longer overwritten when the public IP equals the SSH host. (same answer)
5. **No `-only` and `-skip` now.** A deploy is idempotent, so a second run converges; a BACKLOG row records the deferral. No new flag, no seventh task. (same answer)
6. **A config file that cannot be written is a warning at N and a failure at N+2** (`PersistFailureFatal`). (same answer)
7. **Validation runs in `Deploy`, before the first connection**, not in `Load`; `-list`, `-remove` and `mesh list` stay usable on a state file that fails validation. (same answer)

## Context

**The pipe.** The centralized mode is `Load(mesh-state.json) -> detectEndpoints -> for each node: generate config, push over SSH` (`main.go:141`, `:176`; `pkg/mesh/deploy.go:17-100`). In ETL terms the extract step is a JSON parse, the load step is a root shell on each node, and the steps between them are missing in three places: the transform has no validation and no encoding (the state's strings become shell text), the load has no result (a node's outcome is an `error` that ends the whole run, or a printed warning), and one derived value, the node's endpoint, is decided by a rule that is wrong for a class of meshes. The two operating modes stay separate: this pipeline never reads or writes a `PeerStore` (ADR-0002, Out of Scope); T3 adds a test that fails if `pkg/mesh`, `pkg/ssh` or `pkg/wireguard` imports `pkg/node`, `pkg/daemon` or `pkg/discovery`.

## Decision

1. **A per-node result and one summary.** `Deploy` visits the nodes in sorted hostname order (a map today) and records one `NodeResult{Hostname, Phase, Err, Warnings}` per node, where `Phase` is the step that failed (`detect`, `connect`, `install`, `apply`, `routes`, `persist`). A node that failed in `detect` is not dialled again in the apply loop. After the last node `Deploy` returns `nil` when every node succeeded and otherwise a `*DeployError` whose text lists every failed node with its phase and the underlying error, one line each, and the nodes that were configured; `main.go:176-181` is unchanged (it already prints the error and exits 1). Nodes that succeeded stay configured; the desired state of a failed node is still part of the others' configs, because the state file, not reachability, is the truth. A write failure of the config file is a warning in the node's result at N (printed in a `Warnings:` block after the last node) and a failure when `PersistFailureFatal` is set (M's decision 6). The wg-quick text is rendered at the start of the node's step, before the first connection: a render refusal is a `persist` failure with no command sent to that node. `DeployError` unwraps to the node errors (`errors.Is` and `errors.As` reach them). This is the stateless step C after the load: `deployNode(hostname, node) NodeResult` has no state beyond its arguments, and the report is a pure fold over the results.
2. **A validated state, before the first connection.** `Mesh.Validate() []Finding` is a pure function over the loaded `Mesh` and is the first thing `Deploy` calls (M's decision 7). Each finding names the field, the node, the rule and a class. *Class A* (refused at N): any character outside the safe set `[A-Za-z0-9._:/,@%+=\[\]-]` in `InterfaceName`, `PublicKey`, `PublicEndpoint`, `Network`, `RoutableNetworks` entries and `SSHHost`; a control character or a space anywhere in those values; an empty `InterfaceName`; a value that starts with `-` (it would reach `wg` or `ip` as an option; review 2026-11-15); a missing or unparsable `MeshIP`. *Class B* (a warning at N, refused when `StrictState` is set at N+1): an interface name outside `ifname.ValidateLinux`, a `Network` or `RoutableNetworks` entry that `net.ParseCIDR` rejects, a `PublicEndpoint` that is not `host:port` with a port in 1 to 65535, a `PublicKey` that is not 44 base64 characters, a `ListenPort` or `SSHPort` outside 1 to 65535, a mesh IP outside `Network`, two nodes with one mesh IP or one public key, a non-empty `Network` that `net.ParseCIDR` rejects, where today `generateConfigForNode` prints a warning and uses `/16` (an empty `Network` silently means `/16` today and stays silent) (`deploy.go:266-270`). `PrivateKey` is not a shell argument: it is file content and stdin, guarded by the T2 refusal of newline, carriage return and NUL, so it has no rule here. The grammars are permissive supersets of what `wg`, `ip` and `systemctl` accept for these fields; they are measured against no node (not run), which is why class B warns first.
3. **One owner of shell quoting, and a guard.** `ssh.Quote(s string) string` returns `s` unchanged when it consists only of the safe set above without `[` and `]` (glob characters in `sh`, so an IPv6 endpoint `[fd00::1]:51820` is quoted; review 2026-11-15) and otherwise wraps it in single quotes with embedded quotes escaped (the rule of the existing `shellQuote`); the empty string becomes `''`. `ssh.Cmd(name string, args ...string) string` joins a constant command name and quoted arguments. All 29 builders and the 7 appends go through `Cmd` (or build the wg-quick text with `Quote`): the 16 reachable ones for the fix, the 13 unreachable ones because the guard would otherwise need an exception that the next caller inherits. For a valid state the bytes sent to the node do not change (a value in the safe set is not wrapped), which T2 proves with the command text recorded from the unchanged code before the migration. From T3 on `Deploy` refuses a hostile state before any command (class A), so the hostile-value proof of T2 drives the builders and the renderer directly, and a Deploy-level assertion checks the refusal. `GenerateWgQuickConfig` returns `(string, error)` and refuses a value with a newline, carriage return or NUL, which cannot be quoted on a line-oriented file; its three callers pass the error up. `TestNoUnquotedRemoteCommand` parses the three packages and fails on the first argument to `Run`, `RunQuiet`, `RunWithStdin` or `Start` that is neither a string constant nor a `Cmd` call whose command name is itself constant (`Cmd(routes.ConnectedRouteCmd(...))` is the one named exception: `Cmd` quotes only its arguments, so there the safety rests on the parsed network and the checked interface name of `pkg/routes`, as Out of Scope says) (a constant suffix such as `" 2>/dev/null || true"` may be concatenated to one); its limit is the receiver-name and call-shape match, which T2 states and mutation-tests.
4. **One pure endpoint decision.** `resolveEndpoint(node, allPrivate, publicIP, probed) endpointDecision` in `pkg/mesh` replaces the three writes at `deploy.go:139-147`. Order: (a) a `public_endpoint` already in the state wins (M's decision 4); (b) the SSH host is a private IP address and every node's SSH host is private: `net.JoinHostPort(sshHost, listenPort)` (M's decision 3; `JoinHostPort` also brackets an IPv6 literal, where today `"%s:%d"` produces an invalid endpoint); (c) the probed public IP equals the SSH host: `<ssh host>:<listen port>`, as today; (d) otherwise behind NAT, no endpoint, as today. A node whose SSH host is a private IP address is not probed (its public IP can only differ), so an offline mesh no longer waits for curl at all; a DNS name is never classified private (the operator's resolver is not consulted). The decision carries a `Reason` that the deploy prints, so the operator sees why a node has or has no endpoint.
5. **Staging, the two-release rule.** No wire byte changes and no state field is added (`public_endpoint` exists), so there is no capability version. N (the release that ships T1 to T6): quoting, the control-character refusal in the wg-quick renderer, class A refusal, continue-and-report, the endpoint rule and the skipped probe act at once, because each either leaves the bytes sent for a valid state identical, refuses only a value no working deploy carries, or changes only a run that already failed or a mesh that has no working tunnel today; class B and the persist warning are reported. N+1: `StrictState` is set, so class B is refused (a one-line change). N+2: `PersistFailureFatal` is set, so a config file that cannot be written fails the node. Each flip is a deferred follow-up with its own release note. M's decisions 1, 2, 3, 4 and 6 are what these rows implement.

What would make this decision fail: (a) a builder that passes an unquoted value, caught by the guard test and, for the valid-state bytes, by the recorded command text of T2; (b) a working state refused at N, caught by the saved-state fixtures of T3 (the JSON example in `docs/centralized-mode.md`, around lines 168-185, with its placeholder keys replaced by well-formed ones, and a hostname-endpoint state must produce no finding; with the placeholders it must produce only class B key findings); (c) a deadlock from taking `m.mu` twice in the per-node path, caught by T4; (d) the endpoint rule applied to a mixed mesh, caught by the table test of T5. All four can be red only after each task's first step, against compiling stubs so the first failing run fails on assertions.

## Alternatives Considered

- **Fix each issue where it shows.** Rejected: that is how the class arose (29 builders, none quoting; six exits; three endpoint writes). The next builder, written beside these, would copy an unquoted `Sprintf`; the guard test fails the build instead.
- **Quote only the sites the issue names (`config.go:50`, `persist.go:23`).** Rejected: the issue lists two sites of sixteen reachable ones, and `addOrUpdatePeer` (public key, endpoint, allowed IPs) and the route commands carry the same values.
- **Validate in `Load` only, and trust the rest.** Rejected as the sole defence: a value that gets into `Mesh` by another path (a future import command) would skip it, and validation answers "is this a deployable state", which is a property of `Deploy`. Quoting is the second, independent layer, and `ApplyFullConfiguration` already calls itself "defense-in-depth" for the same pairing. Validation in `Load` stays an open question (7).
- **Reuse `ifname.Validate` as it is.** Rejected: it reads `runtime.GOOS` and on macOS requires `utun<N>`, so a deploy from a Mac to Linux nodes would refuse every `wg0`.
- **Replace the string-taking `Run` with an argv API (`Run(name, args...)`) so quoting cannot be forgotten.** Rejected for now: the commands use `||`, redirections and `&&`, which an argv API cannot express without a shell string anyway; `Cmd` plus a guard test gives the same safety with a diff of one call per site.
- **Run the nodes in parallel and fail the run only at the end.** Rejected here: nothing in the four issues asks for it, the sequential order is what makes the summary readable, and `Deploy` holds `m.mu` for the whole loop (kept from PR #842).
- **Abort remains the default, with `-keep-going` as an opt-in.** Rejected by M's decision 1: it is the strictest two-release reading, but the failing run is the only run continue-and-report changes, and its exit code stays non-zero.
- **Pick the LAN endpoint per receiver.** Rejected by M's decision 3: an RFC 1918 overlap between two sites would point a node at an unrelated machine.

## Component / Boundary Impact

- `pkg/ssh`: gains `Quote`, `Cmd` and the test-support package `pkg/ssh/sshtest` (an in-process SSH server that records commands; imported only by tests); it keeps one reason to change, how a command reaches a node. `NewClient` and the host key code are untouched.
- `pkg/wireguard`: its commands are built with `ssh.Cmd`; `GenerateWgQuickConfig` returns an error. The local-apply functions the daemon uses (`SetPeer`, `RemovePeer`, `GetPeers`, ...) are not touched; they run `wg` through `os/exec` with an argv, not a shell.
- `pkg/ifname`: gains `ValidateLinux`; `Validate` calls it.
- `pkg/mesh`: gains `validate.go` (the state rules), `report.go` (the result and the error) and `endpoint.go` (the endpoint decision); `deploy.go` becomes a loop over `deployNode`. `pkg/mesh` imports nothing from `pkg/node`, `pkg/daemon` or `pkg/discovery`, and a test says so.
- `main.go`: unchanged (M's decision 5 adds no flag); the centralized block is `main.go:92-190`, disjoint from the daemon flags ADR-0002 T10 adds.

## Implementation

See `tasks/README.md`. Seven tasks in six waves (T7 was added on 2026-11-15 for issue #894 item 1, verified in `pkg/mesh/deploy.go`) (they share `deploy.go` and run one after another on one branch): T1 the quoting primitive and the Linux interface grammar, T2 every remote command through it plus the guard and the fake SSH server, T3 the state validation, T4 the per-node result and continuing past a failed node (#865), T5 the endpoint decision (#866), T7 the connected route restore after removing an own-network route (#894 item 1), T6 specs, release note and backlog rows.

## Consequences

- **Positive:** a crafted or corrupted state file can no longer execute a command on a node (#868): a metacharacter is refused before the first connection and, as a second layer, quoted; a down node no longer blocks the others and the operator gets one list instead of the first error (#865); an all-LAN mesh comes up (#866); the next remote command written in these packages cannot skip quoting without failing a test.
- **Negative:** the full effect needs three releases (class B at N+1, the persist failure at N+2). Until N+1 a malformed but metacharacter-free value is still sent (quoted, so inert, and the node's own `ip` or `wg` rejects it). Continue-on-failure means that after a failed run some nodes are one generation ahead of others; the summary names which, and a second run converges. The private-address rule does not help a mixed mesh (M's decision 3); `public_endpoint` remains the answer there.
- **Neutral:** `GenerateWgQuickConfig` changes signature (internal; three callers). The 13 unreachable builders are migrated rather than deleted, so dead code now carries quoting (deletion is a BACKLOG row). `docs/centralized-mode.md` and the centralized spec say that a node whose public IP differs from its SSH host gets no endpoint; T6 amends both and the one-line description of the NAT rule in `README.md` (line 108 on 2026-11-15). `node.BehindNAT` is now false when an operator-written endpoint or a rule (b) or (c) endpoint is used; it is read only by `wgmesh -list` from the state file and Deploy never saves, so no behaviour depends on it.

## Risks

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| A working state is refused at N (a hostname endpoint, a route written as a bare IP, an interface name with a dot) | Med | High | class A is only characters a shell or wg-quick interprets; the forms `ip` and `wg` tolerate are class B and warn at N; T3 has saved-state fixtures that must give no finding |
| The quoted command differs from today's for a valid state and a node's `ip` or `wg` call changes | Low | High | a value inside the safe set is not wrapped; T2 records the command text produced by the unchanged code before migrating and asserts byte equality afterwards |
| Continuing after a failure pushes a config to the remaining nodes that depends on the failed one (a peer that never came up) | Med | Low | the config lists every peer from the state regardless of reachability (as today); the failed node's peers keep it as a peer, and a later deploy of that node converges |
| The guard test's receiver-name and call-shape match misses a builder through a helper or a variable | Med | Med | T2 states the limit, mutation-tests three shapes (a `Sprintf`, a variable, a concatenation), and the builders live in three packages the test lists by name |
| The private-address rule gives a node an endpoint nobody can reach (an SSH host reached through a bastion) | Low | Low | the rule applies only when every node's SSH host is private, and an endpoint that cannot be reached leaves the tunnel where it is today (no tunnel started by this side); `public_endpoint` wins and is the documented override |
| A DNS-name SSH host on a LAN is not treated as private | Med | Low | the rule is not applied and behaviour is today's; the operator sets `public_endpoint`; documented in T6 |
| Class A refuses a state at N for a character that a hand-edited but working state carries (`+`, `=` are allowed; a space in a route list is not) | Low | Med | refused with the field, the node and the rule in the message; M's decision 2 chose class A refusal at N |
| `wg-quick` does not run `PostUp` through a shell as this record states | Low | Low | quoting is correct under either reading; the premise was read from wg-quick(8), not run on a node (not verified) |

## Rollback

Nothing persisted changes shape: no state field, no wire byte, no file format on the node except that the wg-quick text is byte-identical for valid values. Reverting N restores the unquoted builders, the abort-on-first-failure loop and the old endpoint rule; a node configured by N keeps a valid config. Setting `StrictState` or `PersistFailureFatal` back to `false` returns to the N behaviour without a data change. The node-side files written by N are the same files the old code wrote. `pkg/ssh/sshtest` and the fixtures stay in the repository.
